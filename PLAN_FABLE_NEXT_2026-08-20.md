### 1.3 Подключение расширений

- **Статически (`import`)** — `@modkitx-x3/extensions/<id>` и наборы `imagesOnly`, `modelsOnly`,
  `media`, `structuredText`, `archivesOnly`, `documentsOnly`, `everything`. Импорт и есть решение о
  доверии; линкуется только то, что само декларирует `trusted-in-process`.
- **Динамически** — папки пользователя: Electron (живьём), PWA (File System Access, дайджесты
  считает страница, worker-only), VS Code (workspace + настройка), Node-фасад.
- **Отключение расширений и кодеков** — страницы настроек в Electron и VS Code; кодек выключается
  на уровне инвентаря (`disabledContributions`), запись остаётся видимой, а неоткрывшийся файл
  называет причину: `x3.host/candidate-suppressed` вместо молчания.

### 1.4 Способы использования

- **Node-библиотека** — `createModkit({ modules, extensions, roots, writableRoots })`.
- **Веб-компонент** — `<modkit-viewer src=…>`; контракт встраивания (CSP, origin, Shadow DOM)
  измерен в Chromium, не предположен.
- **Минимальная сборка** — субпути на каждую поверхность, `sideEffects: false`, и гейт
  `scripts/test/minimal-build.test.ts` из пяти эталонных конфигураций.

## 2. Очередь выполнена — по этапам

### Этап 1. Паритет редактирования

1. ✅ **Мутирующие операции в VS Code.** Формы операций проходят через JSON-транспорт, применяют
   изменения и сохраняют их тем же координатором, что остальные хосты.
2. ✅ **Панель байтов записи архива в VS Code.** Выбор записи использует стандартную операцию
   `container.extract` и открывает точные байты в общей hex-поверхности.
3. ✅ **Живой круг MP3 в PWA.** Детерминированный валидный образец отгружается в Chromium-тесте;
   тег меняется, сохраняется и читается заново с диска.

### Этап 2. Сохранение изображений

4. ✅ **Пиксельное редактирование PNG.** Electron разрешает редактор только при наличии writer
   `png/rgba8@semantic`; редактор формирует семантический RGBA intent, а перекодирует кодек.

### Этап 3. Архитектурные долги, названные агентами

5. ✅ **Байты записи архива как хост-задача.** SDK принимает точный `entryId`, а общий id
   `container.extract` принадлежит core; приложения больше не угадывают codec-specific имя.
6. ✅ **Координаты доказательства публикует кодек.** Fidelity-записи живут в codec contribution;
   host соединяет их с реальными `providerVersion` и `artifactDigest` из инвентаря.
7. ✅ **`createSettingsUi.extraGroups`.** Electron использует одну поверхность с четырьмя
   группами: Appearance, Extensions, Codecs, File associations; группы имеют reload/destroy hooks.
8. ✅ **VS Code `CustomEditorProvider`.** Нативные dirty, Ctrl+S, revert и backup связаны с тем же
   буфером webview; кнопки Save делегируют сохранение VS Code, а не обходят его документную модель.

### Этап 4. Оптимизации сборки (не дефекты)

9. ✅ PWA не импортирует корневой barrel `ui`; каталог сцен webview VS Code импортирует только
   объявленные им UI-субпути. Регрессию VS Code ловит source-boundary тест. После esbuild выигрыш
   мал (94 байта в контрольной PWA-сборке и 98 байт в webview), потому что tree-shaking уже работал;
   важный результат — явная и проверяемая граница зависимостей.

## 3. Честные ограничения

- **Видео не редактируется** — писателя нет, и притворяться нечем.
- **VS Code не запускается в этой среде**: что webview отрисуется в настоящем редакторе и что
  `showOpenDialog` вернёт папку — не проверено живьём.
- **Диалоги выбора папки в браузере** требуют жеста пользователя, которого встроенная панель дать
  не может: подменяется ровно handle, всё ниже — настоящее.
- **Нет лицензированного проигрываемого медиа-корпуса в репозитории**; MP3-доказательство строит
  детерминированный валидный образец во время теста.
- `text-json/toml/xml/yaml` не открываются в браузере — парсеры не собраны для worker; `jsonc` по
  той же причине не проверяет синтаксис.
- Пакеты `@modkitx-x3/*` не публикуются: «подключить» сегодня = workspace/git-ссылка.

## 4. Решения по открытым вопросам — приняты 2026-08-20

Подробности и обоснование — в `PLAN_SOL_2026-08-20.md` §3.

1. **npm — не сейчас**; распространение через git-зависимость и `pnpm pack`-тарболлы, с тестом,
   доказывающим установку в чистый проект. Публикация имени необратима и остаётся за человеком.
2. **Расширения по URL для embed — allowlist origin'ов, запекаемый развёртывающим сборку.** Не
   «страница называет и код, и аттестацию» (не проверяет ничего) и не PKI (её здесь нет). Страница
   не может добавить origin — это и есть искомое свойство. Реализовано через
   `MODKIT_EMBED_EXTENSION_ORIGINS` + `extension-catalog`; Chromium доказывает разрешение
   build-pinned origin и отказ page-invented origin до сетевого запроса.
3. **Медиа-корпус — решается частично, и ровно та часть, что решаема.** MP3 из валидных кадров
   тишины строится детерминированно и по-настоящему декодируется; для ogg/mp4/webm — шаг фикстур
   через `ffmpeg`, если он есть, с **видимым** пропуском доказательства, если нет. WAV генерировать
   бессмысленно: кодека для него нет.
4. **Кириллица для Saira — отложено с явным триггером**: первая же локализованная строка интерфейса.
   Сегодня строки английские, а русские документы приложение не рендерит.
5. **Раскладка Nexus — остаётся устанавливаемой темой**, не умолчанием: это решение о внешнем виде
   продукта.

## 5. Рабочие правила (выяснены дорогой ценой)

- Агент не запускает `pnpm check` одной командой на переднем плане: сторожевой таймер снимает его
  после 600 с молчания. Гейт запускается фазами.
- Больше двух параллельных агентов машина не тянет; упавшее под нагрузкой перепроверяется в
  одиночку, прежде чем ему верить.
- `dist-app` собирает Root после слияния. **Скриншот пользователя может прийти со сборки агента,
  сделанной до правки** — проверять фактом, а не спорить.
- `tsc -b` после `pnpm build` разваливает бандлы: строго `pnpm build` → `pnpm test`.
- Новый субпуть в `exports` требует записи в `PUBLISHED_ENTRIES` (`scripts/test/bundle.test.ts`),
  иначе `pnpm bundle` его прунит.
- Маркер поверхности в гейте сборки — строка её собственного кода, **не** имя part: словарь
  `parts.ts` едет в любой модуль, штампующий часть.
