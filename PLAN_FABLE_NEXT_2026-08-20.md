### Подключение расширений

- **Electron** — папки пользователя, проверено живьём.
- **PWA** — папки пользователя через File System Access, дайджесты считает сама страница
  (WebCrypto), расширения выполняются только в worker. Модель доверия зафиксирована: подписи нет,
  дайджест **не подтверждает происхождение**, он лишь фиксирует байты между чтением и исполнением.
- **VS Code** — папки рабочей области + настройка `modkit.extensions`, через тот же
  `loadExtensionRoots`; отказы видны в output-канале. Доказано тестами.
- **Node-библиотека** — два списка (`extensions` — свои, `userExtensions` — пользовательские),
  каждый каталог грузится независимо, сломанный становится записью, а не исключением.

## 2. Новые линии (запрос владельца, 2026-08-20)

### 2.1 Modkit как Node-библиотека — ✅ сделано (`bfa3406`, `2cac6b3`, `22e62c0`)

«модкит должно быть легко подключить как nodejs библиотеку» — всё нужное существовало, но было
размазано по пяти модулям плюс топология, которую потребитель писал бы сам. Теперь:

```ts
import { createModkit } from '@modkitx-x3/host/node'

const modkit = await createModkit({
  extensions: ['./node_modules/@my-app/codecs'], // свои кодеки
  roots: [projectDir], // откуда можно открывать
  writableRoots: [assetsDir], // где можно сохранять
})
const opened = await modkit.open(join(assetsDir, 'logo.png'))
// opened.session — источники данных; opened.editing?.editorPorts — путь сохранения
await modkit.close()
```

Политика безопасности фиксирована, а не настраиваема — фасад это место, где умолчания становятся
политикой: расширения исполняются только в worker (`allowTrustedInProcess` здесь не опция); чтение
ограничено `roots`; запись ограничена `writableRoots` самим бекендом, так что грант не может обещать
больше, чем файловая политика. Доказано шестью тестами, написанными как код потребителя: открытие
PNG worker-brokered, отказ вне roots до любого обращения к диску, unresolved вместо исключения,
полный цикл правки байтов с коммитом в настоящий файл.

**Статический import — сделано.** `import { images } from '@modkitx-x3/extensions'` →
`createModkit({ modules: [images] })`: код расширения попадает в бандл приложения, исполняется
in-process (импорт и есть решение о доверии; гейт всё равно объявляет
`x3.host/full-process-authority`), а несовместимое честно исключается с причиной. Кураторские
наборы: `imagesOnly`, `modelsOnly`, `media`, `structuredText`, `archivesOnly`, `documentsOnly`,
`everything`. Отключение кодека — `disabledContributions`: запись остаётся в инвентаре (иначе её
не включить обратно), активация запрещена хостом.

**Ограничение (решение владельца):** пакеты `@modkitx-x3/*` не публикуются. «Подключить» сегодня =
workspace/git-ссылка на лабораторию. Публикация — открытый вопрос владельца (§4.3).

### 2.2 Встраиваемые веб-компоненты — ✅ сделано (A13, `0a5b7a9`)

«подключать модкит и расширения в обычные веб-компоненты и встраивать внутри веб-сайта, например
для отдельных вьюверов»:

```html
<script type="module" src="https://static.example/modkit/embed.js"></script>
<modkit-viewer src="./assets/diagram.svg"></modkit-viewer>
<modkit-viewer src="./data/table.csv" view="table"></modkit-viewer>
```

Контракт: тот же worker-brokered путь открытия с проверкой дайджестов, что и в PWA; один хост на
`asset-base`, общий для всех элементов страницы; Shadow DOM — стили сайта не протекают внутрь, наши
не текут наружу; честный отказ в самом элементе при 404/не-CORS; v1 только просмотр (редакторские
сцены отбрасываются — как PWA до A8). Расширения = аттестованный каталог сборки; **подключение
пользовательских расширений по URL — сознательно вне объёма v1**: этому нужна история доверия
(аттестация каталога по URL), она уходит владельцу как вопрос.

Доказано живым автоматическим тестом: 13 утверждений в настоящем Chromium (CSP измерена директива
за директивой, кросс-origin в обе стороны, стили не текут ни туда, ни обратно), 30 — в Node.
Фирменная таблица стилей теперь пригодна для shadow root как есть (`:root, :host`).

   вложенного источника хостом. Плюс панель записи в VS Code (¹ выше).

### Известные честные ограничения

- **Видео не редактируется** — писателя нет, и притворяться нечем.
- **Нет проигрываемого медиа в репозитории** (WebM без кластеров, MP3 в один кадр) — кодеки их
  принимают, но воспроизводить нечего.
- **Диалоги выбора папки в браузере не проверены живьём** — нужен жест пользователя, которого
  встроенная панель не даёт. Всё ниже диалога проверено с подставным handle.
- `text-json/toml/xml/yaml` **не открываются в браузере** — парсеры не собраны для worker; каталог
  и настройки называют причину.
- **VS Code не запускается в этой среде** — плагин доказан тестами и сборкой, не живым редактором.

## 5. Рабочие правила, выясненные дорогой ценой

- **Агент не запускает `pnpm check` одной командой на переднем плане** — сторожевой таймер снимает
  его после 600 с молчания; гейт идёт фазами.
- **Больше двух параллельных агентов машина не тянет** — упавшее под нагрузкой перепроверяется в
  одиночку, прежде чем ему верить.
- **`dist-app` собирает Root после слияния**, а не каждый агент у себя.
- **`tsc -b` после `pnpm build` разваливает бандлы** — `scripts/test/bundle.test.ts` увидит это как
  красное; последовательность строго `pnpm build` → `pnpm test`.
