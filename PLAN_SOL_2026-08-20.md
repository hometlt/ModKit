## 1. Правила работы (выяснены дорогой ценой — они сэкономят тебе часы)

1. **Гейт запускается фазами, не одной командой.** Сторожевой таймер снимает агента после 600 с
   молчания, а `pnpm check` под нагрузкой идёт дольше. Порядок:
   `pnpm build` → `pnpm lint && pnpm format:check` → `pnpm exec tsc -p tsconfig.tooling.json` →
   `pnpm exec vitest run <свои каталоги>` → `pnpm test` → остальные `*:check`. Между фазами пиши
   строку вывода.
2. **Ничего не запускай параллельно с гейтом в том же дереве.** `tsc -b` после `pnpm build`
   пересобирает `packages/*/dist` в многофайловый вид и разваливает бандлы: тест
   `scripts/test/bundle.test.ts` покажет «still imports its own modules», и ты будешь чинить
   несуществующий регресс. Я потерял на этом прогон — не повторяй.
3. **Упавшее под нагрузкой перепроверяй в одиночку**, прежде чем считать это дефектом. Ошибки вида
   «Failed to load url ajv/…» — это состояние pnpm-стора, а не код.
4. **`dist-app` собирает Root после слияния.** Не коммить `apps/*/dist-app/**` и
   `scripts/bundle-hashes.json`: собери, проверь, потом `git checkout --` этих путей.
5. **Новый субпуть в `exports`** требует записи в `PUBLISHED_ENTRIES`
   (`scripts/test/bundle.test.ts`), иначе `pnpm bundle` его вырежет и dist окажется пустым.
6. **Маркер поверхности в тестах сборки — строка её собственного кода, не имя part.** Словарь
   `packages/ui/src/parts.ts` — один массив со ВСЕМИ именами, он едет в любой модуль, штампующий
   часть. Маркер по имени части репортит словарь как поверхность (я на этом уже попался).
7. **Три жёстких переписи ломаются при добавлении контрибушенов**:
   `packages/testkit/test/text-data.test.ts`, `scripts/app-extension-sets.mjs`,
   `scripts/check-apps.mjs`. Плюс `contributes:check` для VS Code.
8. **Запреты, которые проверяются гейтами**: слово `capability` не может быть ключом
   объекта/схемы; format id (`image-png`, `archive-zip`, `zip`…) не должен появляться в исходниках
   `core/sdk/vfs/host` **даже в комментарии**; `!` non-null не разрешён; никаких `as any`,
   `@ts-ignore`, управляющих символов; `VIEWER_CSP` в `packages/ui` не меняется.
9. **Сиблинг-репозиторий `modkitx` — строго только для чтения.** Никогда ничего в нём не удаляй и
   не правь; импорты из него запрещены.
10. **Коммиты — на своей ветке, без push.** Сообщение заканчивается
    `Co-Authored-By: Claude Sol <noreply@anthropic.com>`.

### Стандарт доказательства

Этот проект не принимает «должно работать». Каждая задача ниже требует **живого** доказательства
там, где среда это позволяет, и честного заявления там, где нет:

- **Electron** запускается здесь: `cd apps/electron && node scripts/build-app.mjs && node_modules/.bin/electron.CMD electron/main.cjs --open <папка> --selftest --enable-logging`.
  Пиши утверждения в самопроверку (`apps/electron/src/renderer.ts`), гоняй на маленькой папке —
  большая с 3D-моделью идёт минутами. Байты проверяй на диске, а не по UI.
- **Браузер** запускается здесь: образцы — `apps/web/test/{boot,embed,edit-panel}.test.ts`
  (реальная сборка по HTTP + playwright-core). Подменять можно **ровно** то, что даёт жест
  пользователя (handle из пикера), остальное — настоящее.
- **VS Code здесь не запускается.** Доказывай тестами над структурными подделками и сборкой
  бандлов, и **прямо пиши в отчёте**, что осталось непроверенным живьём.

## 2. Состояние проекта

Полная картина — `PLAN_FABLE_NEXT_2026-08-20.md` (ред. 3). Коротко, чтобы не переключаться:

**Работает и доказано живьём:** просмотр всех поддерживаемых форматов в Electron, PWA и во
встраиваемом веб-компоненте `<modkit-viewer>`; редактирование текста и байтов там же; мутирующие
операции (добавить/удалить запись ZIP, поля PNG, теги MP3) в Electron и PWA; подключение и
отключение расширений **и отдельных кодеков** через страницы настроек Electron; подключение папок

**Работает, доказано тестами (живьём нельзя):** плагин VS Code — открытие, просмотр,
редактирование текста и байтов, подключение расширений через настройки.

**Ключевые швы, на которые ты будешь опираться:**

## 3. Решения по открытым вопросам (приняты, действуй по ним)

**1. Публикация в npm — не сейчас; распространение через tarball.** Публикация имени необратима и
остаётся за человеком. Но линия «modkit как библиотека» не должна её ждать: `pnpm pack` уже
используется в `scripts/test/reference-codecs-packed.test.ts`, где чужой потребитель ставит пакеты
из тарболлов. Значит рецепт установки есть — его надо оформить и доказать (задача 1.4).

**2. Доверие расширениям по URL во встраиваемых компонентах — allowlist, пинуемый развёртывающим.**
Не «страница называет и код, и его аттестацию» (это не проверяет ничего) и не PKI (её здесь нет).
Правило: список разрешённых origin'ов **запекается в сборку `embed.js` тем, кто её развернул**;
страница может указать каталог только с этих origin'ов, и каждый файл по-прежнему проверяется по
дайджестам каталога. Страница не может добавить origin — это и есть свойство, ради которого всё
делается. Задача 3.4; если возьмёшься, начни с того, что запрет «страница добавляет origin»
доказывается тестом.

**3. Медиа-корпус — частично решаемо, и решай ровно ту часть, что решаема.** Кодеки здесь:
mp3, ogg, mp4, webm (WAV нет — настоящий WAV было бы просто сгенерировать, но открывать его нечем).
MP3 из валидных кадров тишины строится детерминированно и **по-настоящему декодируется** — расширь
генератор фикстур до ~1 секунды кадров. Для ogg/mp4/webm нужны настоящие энкодеры: сделай шаг
фикстур, который использует `ffmpeg`, если он есть в PATH, и **явно помечает доказательство
пропущенным**, если его нет. Пропуск должен быть виден, а не молчалив.

**4. Кириллица для Saira — отложено, с явным триггером.** Сегодня строки интерфейса английские, а
русская документация — Markdown, который приложение не рендерит, поэтому проблемы у пользователя
нет. Триггер: **в момент, когда локализуется хоть одна строка интерфейса**, нужен кириллический
субсет или замена шрифта на тот, у которого он есть. Не делай сейчас.

**5. Раскладка Nexus — остаётся устанавливаемой темой, не значением по умолчанию.** Это вкусовое
решение о внешнем виде продукта; оно за человеком. Не меняй умолчание.

## 4. Задачи

Порядок важен: этап 1 доводит до паритета то, что уже спроектировано, этап 2 добавляет новую
возможность на готовых швах, этап 3 — архитектурные долги, названные предыдущими агентами.

### Этап 1. Паритет редактирования

**1.1. Мутирующие операции в VS Code** — единственный хост без них.
Цель: панель Edit в webview, предлагающая `edit.structure`/`edit.content` (ZIP) и `edit.field`
(PNG/MP3), с коммитом через арм S14.
Где смотреть: `apps/web/src/edit-panel.ts` и `apps/web/src/edit-operations.ts` — ближайший образец
(in-page); `apps/electron/src/editor-ports.ts` — как арм адаптируется к портам через границу;
`apps/modkit-vscode/src/{webview,bridge,host}.ts` — куда встраивать.
Правила: формы ключуются **по обработчику кодека**, не по глаголу (`edit.field` — это
`{keyword,text}` у PNG и `{text}` у JPEG); операция без формы объявляется неподдержанной с
причиной, а не рисуется контролом, который откажет; отказы кодека/хоста/координатора сохраняют
свою причину дословно; после коммита вкладка переоткрывается (ревизия сдвинулась) — используй
`EditorArea.close(entryId)`, он для этого и добавлен.
Не импортируй таблицу форм из другого приложения: политика форм принадлежит приложению.
Приёмка: тесты над структурными подделками (правило предложения, форма каждой операции, отказ,
переоткрытие) + прямое заявление, что живьём не проверено.

**1.2. Панель байтов записи архива в VS Code** — до паритета просмотра.
Сегодня список записей есть, а панели с байтами выбранной записи нет. Образец —
`apps/web/src/views.ts` (составная сцена `entries`: `namespaceViewer` + панель, читающая байты
через немутирующую операцию извлечения кодека).

**1.3. Живой круг MP3 в PWA.**
Форма и префилл ID3 доказаны только в Node, потому что `apps/web/public/samples/` не отгружает
MP3. Сгенерируй образец (см. решение 3 выше: валидные кадры тишины) и доведи живой тест
`apps/web/test/edit-panel.test.ts` до полного круга: запись тега → байты в write-log → переоткрытая
вкладка показывает значение.

**1.4. Рецепт установки modkit как библиотеки** (решение 1).
Цель: чужой проект ставит modkit **без публикации в npm** и получает работающий `createModkit`.
Сделай: раздел в `docs/GUIDE_DEVELOPER_RU.md` с двумя способами (git-зависимость и `pnpm pack`
тарболлы) и тест, который это доказывает — упаковать `core/sdk/vfs/host` + один пакет расширений,
поставить в чистый временный проект, открыть файл, проверить дескриптор. Образец процедуры —
`scripts/test/reference-codecs-packed.test.ts` (он уже пакует и ставит тарболлы).

### Этап 2. Сохранение изображений

**2.1. Пиксельное редактирование PNG.**
Сейчас редактор изображений в Electron честно read-only: рендерер не должен перекодировать
пиксели сам. Но писатель-энкодер существует и коммитит — `org.modkitx/png-encoder-writer`,
фасет `png` / `rgba8` / `mutate` / `semantic` (доказательство:
`packages/host/test/media-edits.test.ts`, describe «A5 Path B»).
Сделай: провести этот писатель по фасету до редактора изображений (`resolveFormatWriter` с явным
`representationId: 'rgba8'` и `minimumRoundTrip: 'semantic'`), включить сцену как `editable`,
снять `readonly` и надпись «edits are in memory only», обеспечить политику доказательств для
`semantic` (запись должна цитировать корпус, как это сделано для ZIP в
`apps/web/src/editing.ts`).
Приёмка **живьём**: в самопроверке Electron — изменить пиксель, сохранить, переоткрыть, декодировать
и убедиться, что именно этот пиксель изменился, а размеры сохранились.
Важно: `semantic` означает, что неизвестные байты не сохраняются — метаданные PNG при
перекодировании теряются. Это должно быть **сказано пользователю** перед коммитом, а не обнаружено
им потом.

### Этап 3. Архитектурные долги

**3.1. Байты записи архива как задача хоста.**
Проблема: `NamespaceEntrySource.openEntry` возвращает ссылку (`AssetSourceRef`), которую нечем
открыть, поэтому оба приложения читают запись через codec-specific операцию извлечения — конвенция,
а не контракт. Реши одним из двух способов и обоснуй выбор: либо стандартный id операции «прочитать
запись пространства имён», либо переоткрытие вложенного источника на стороне хоста. Второе сильнее,
но затрагивает `packages/vfs` — оцени.

**3.2. Кодек публикует координаты своего доказательства.**
Записи fidelity сейчас перепечатаны в двух приложениях (`apps/web/src/editing.ts`,
`apps/electron/electron/main.cjs`), и это **цена границы**: платформенный пакет не вправе знать про
zip — гейт границ поймал меня, когда я попытался централизовать их в `packages/host`. Настоящий
ответ: координаты (writer identity, corpusId, conformanceProfile, inputClass) приходят из
инвентаря — от самого кодека. Решение о том, принимать ли доказательство, остаётся у приложения.

**3.3. Точка расширения у `createSettingsUi`.**
Из-за её отсутствия в Electron **две** страницы настроек вместо одной с четырьмя группами. Нужна
опция вида `extraGroups?: readonly Group[]`; после неё — свести Electron к одной странице.

**3.4. Доверие расширениям по URL для embed** (решение 2 выше) — только если этапы 1–2 закрыты.

**3.5. Полный `CustomEditorProvider` в VS Code** — родной индикатор изменений и Ctrl+S. Сейчас
`CustomReadonlyEditorProvider`: сохранение работает, но грязное состояние живёт внутри страницы.

### Этап 4. Оптимизации сборки (не дефекты)

**4.1.** PWA на субпути `@modkitx-x3/ui/<поверхность>` вместо корневого импорта.
**4.2.** Webview VS Code собирает только реально включённые сцены.
Обе — измеримые: до/после по маркерам гейта минимальной сборки.

## 5. Чего не делать

- Не менять `VIEWER_CSP`, не ослаблять CSP приложений «чтобы заработало» — если что-то не проходит,
  причина в коде, а не в политике.
- Не подключать Monaco никуда, кроме Electron.
- Не добавлять Extension Host приложениям с фиксированным набором функций.
- Не выставлять `allowTrustedInProcess` руками: для статической полосы это делает
  `defineLinkedExtension`, и там это и есть смысл.
- Не «чинить» честные ограничения выдумыванием: если писателя для формата нет, правильный ответ —
  отказ с причиной, а не тихое сохранение мусора.
- Не трогать `NexusForgeUI/` (чужой каталог) и сиблинг-репозиторий `modkitx`.
