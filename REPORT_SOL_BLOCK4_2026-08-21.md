# Отчёт Sol — блок 4: стоп на platform-границе CASC

Дата: 2026-08-21

Ветка: `spec/mk3-extension-reference`

Задание: `PLAN_SOL_BLOCK4_2026-08-21.md`

## Результат

Этап 1 остановлен до переноса CASC: настоящая установка StarCraft II обнаружила недостаток
platform-слоя. `FileVfsProvider` не позволяет открыть CASC data-файл размером больше
536 870 912 байт, даже если потребитель явно запрашивает больший `maxBytes`. Реальный
`SC2Data/data/data.000` имеет 1 073 741 824 байта.

По правилу §1 и прямому стоп-условию §5 плана platform не расширялся «заодно» внутри кодека.
Этапы 2–4 не начинались.

## Живое доказательство на настоящей установке

Проверка выполнена только на чтение по пути `C:\Apps\StarCraft II` через опубликованный
file-VFS. Провайдеру и mount были переданы одинаковые лимиты:

- `maxEntries`: 100 000;
- запрошенный `maxBytes`: 2 147 483 648;
- `maxPathBytes`: 4 096.

Маркер `.build.info` открылся как файл размером 678 байт. Открытие
`SC2Data/data/data.000` вернуло:

```json
{
  "name": "ModkitError",
  "code": "x3.vfs/file-byte-budget-exceeded",
  "message": "file provider exceeded its configured byte boundary",
  "context": {
    "path": "SC2Data/data/data.000",
    "bytes": "1073741824",
    "maxBytes": "536870912"
  }
}
```

Установка не изменялась.

### Размер хранилища

В `SC2Data/data` находятся:

- 28 файлов `data.000`…`data.027`, суммарно 29 238 181 277 байт;
- максимальный data-файл — 1 073 741 824 байта;
- 16 локальных `.idx`, суммарно 6 291 456 байт.

Проблема не в попытке загрузить 29,2 ГБ целиком. CASC использует случайный доступ к небольшим
диапазонам внутри больших data-файлов, но file-VFS отклоняет файл по его полному размеру ещё до
первого диапазонного чтения.

## Точная platform-граница

`createFileVfsProvider({ limits })` вызывает `clampVfsLimits` относительно
`DEFAULT_VFS_LIMITS.maxBytes = 512 MiB`. Поэтому запрос 2 GiB без ошибки превращается в 512 MiB.
Затем `FileMount.stat()` и `FileMount.open()` сравнивают с этим значением полный размер файла.

Для разблокировки нужен отдельный platform-дизайн: различить максимальный размер
random-access-файла и бюджет реально прочитанных байтов либо определить иной явный ограниченный
контракт. Просто поднять общий лимит внутри CASC-кодека нельзя: кодек получает `AssetNamespace`,
а отказ происходит ниже него, в VFS.

Дополнительно найден codec-level дефект, который следует исправить после platform-решения:
манифест CASC объявляет маркеры `Data/config` и `Data/data`, а настоящая установка SC2 содержит
`SC2Data/config` и `SC2Data/data`.

## Бюджеты CASC

Runtime-бюджеты перечисления и извлечения не объявлены как реализованные: кодек не дошёл до
`open()` и по-прежнему остаётся `x3.mk2/port-pending`. Численно доказана более ранняя граница:

| граница                                   |                    значение | поведение при превышении                     |
| ----------------------------------------- | --------------------------: | -------------------------------------------- |
| фактический максимум file-VFS             |    536 870 912 байт на файл | `x3.vfs/file-byte-budget-exceeded` до чтения |
| запрошенный в доказательстве максимум     |  2 147 483 648 байт на файл | зажимается до 536 870 912                    |
| необходимый минимум для текущей установки | 1 073 741 824 байта на файл | сейчас недостижим через публичные опции      |

Называть будущие лимиты страниц, записей или извлекаемых байтов как уже работающие было бы
ложным доказательством. Их следует зафиксировать тестами одновременно с platform-решением и
переносом CASC.
