## Крупные разрывы

1. **Семантический SC2-стек отсутствует как система.** В MK2 это не только кодеки: вместе работают
   `data-processing` (schema/catalog/inheritance), `maps-processing` (terrain, regions и служебные
   бинарные части карты), `mods-processing` (dependency/workspace resolver),
   `layouts-processing`, `localization-processing`, `scripts-processing`, `language-contracts` и
   `lsp`. В MK3 есть общие контракты и port-pending envelopes, но нет этой исполняемой цепочки.
2. **Нет runtime/world/agent plane.** MK2 содержит budgeted runtime sessions, канонический World
   linker/scheduler и permission-gated agent operation catalog с двухфазными мутациями. Обычные
   codec operations MK3 не заменяют эти три поверхности.
3. **3D-паритет пока метадатный.** M3/M3A открывается, но MK2 дополнительно декодирует геометрию,
   материалы, скелет, анимации, particle/ribbon effects и рендерит через WebGL/Three/headless.
4. **CASC теперь открывается, installation discovery — нет.** MK3 умеет открыть явно переданный
   корень SC2 через VFS → Host → CASC, но не имеет реестра игр и Steam/Epic/Blizzard discovery,
   которые реализует `games`.

Следующий блок не должен «портировать 13 пакетов» одной задачей. Сначала нужны три контракта,
которые разблокируют несколько строк сразу: language/LSP, game runtime, renderer. После них —
вертикальный SC2 slice `games → mods → data → maps`, потому что отдельный map codec без dependency
resolver и data schema повторит только имя MK2-поверхности, а не её поведение.
