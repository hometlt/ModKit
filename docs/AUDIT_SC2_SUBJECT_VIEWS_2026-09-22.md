# SC2 subject cards, resolved XML and parent-chain audit — 2026-09-22

## Result and evidence boundary

Fixed owner-side projection losses for command pages, production routes, named parent links and vital write metadata, plus corrupt nested XML in the catalog resolved-view operation. These are source and synthetic-test results. They do **not** establish installed VS Code parity with the MK2 examples: the generic card still lacks inline editing and command-grid projection, and the native entity/resolved/parent code lenses are absent.

No installed editor was launched, closed, repackaged or changed. No actual game/package contents were queried. No changes were committed. Existing dirty work was preserved. Only the three Blizzard Data source files, one new Data test file and this report were written by this audit. `resource-chain.ts`, `mod-card.ts`, mod codecs, generated schema, UI, LSP and MCP adapters were not edited.

Path abbreviations below: **B** = `modkit-extensions-blizzard`, **C** = `modkit-core`, **MK2** = read-only `references/modkitmk2`. Line references describe the inspected working sources; concurrent work may shift them.

## Editing boundary

The single-file codec's `edit-field` handler (`B/starcraft2/modules/data/codecs/sc2data/src/codec.ts:428`) invokes the existing surgical patcher and refuses multi-file edits. It does not select a local override destination for a dependency entity. The package card omits `editOperation` entirely (`mod-card.ts:651`), so the new metadata cannot grant it writes.

The authoritative service already separates effective source from destination: `B/starcraft2/modules/data/services/editing/edit-target.js:225` requires the selected root to be the active root and `:232` requires it in `writableRootIds`. `C/packages/host/src/data/index.ts:883` adapts those targets to subject edit-target previews; the host writer retains revision guards. In VS Code, `apps/vscode/src/host.ts:1252` bases ordinary source writing on path/grant policy and excludes remote `modkit-source:` paths; that is not a dependency-to-local-override policy. Opening a dependency's physical file and editing that file is different from overriding it in the selected mod.

The new tests verify the projection publishes no write declarations when no write route is supplied. They do not prove that every installed dependency URI is read-only or that a card edit commits a local override. Those acceptance claims require the host/UI integration and a live editor test.
