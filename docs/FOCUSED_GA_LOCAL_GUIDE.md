# Локальная проверка Focused Product GA

Это руководство ведёт от чистого checkout до локальной проверки и подписанного RC Modkit MK3.
Focused Product GA в этом документе означает локально проверяемую платформу с общими форматами,
StarCraft II и Warzone 2100. Публичный выпуск владелец сделает позже после личного тестирования.

## 1. Подготовьте инструменты

Установите Node.js 22 или новее. В поставку Node.js 22 входит Corepack, через который можно
активировать pnpm 10:

```powershell
corepack enable
corepack prepare pnpm@10 --activate
node --version
pnpm --version
```

Если политика Windows не разрешает `corepack enable`, установите pnpm 10 любым официальным
способом и убедитесь, что `pnpm --version` работает в новом терминале.

## 2. Соберите чистый checkout

Откройте PowerShell в корне репозитория и выполните:

```powershell
pnpm install --frozen-lockfile
pnpm build
```

`--frozen-lockfile` не меняет зафиксированные зависимости, а `pnpm build` проверяет каталоги,
типы и собирает приложения. Полная обязательная проверка запускается отдельно:

```powershell
pnpm check
```

Она заметно дольше обычной сборки, потому что включает тесты, форматирование, схемы, каталоги,
профили, миграционные сверки, документацию и воспроизводимость release-метаданных.

Два коротких гейта отдельно подтверждают границу Focused GA и состав профилей:

```powershell
pnpm priority:check -- --release mk3-ga
pnpm profiles:check
```

Для локального просмотра можно запустить одно приложение из исходников:

```powershell
pnpm --filter @modkitx-x3/web-app app:serve
pnpm --filter @modkitx-x3/electron-app start
```

PWA печатает локальный адрес. Electron здесь запускается из checkout; готового системного
установщика или ярлыка текущий RC не создаёт.

Отдельный hermetic smoke запускает настоящее тестовое окно VS Code и не открывает установленную
игру:

```powershell
pnpm --filter @modkitx-x3/modkit-vscode smoke:vscode -- --focused-ga
```

## 3. Выберите профиль

Профили фиксируют состав общей платформы и расширений; они не создают отдельные форки приложения.

| Задача                           | Профиль                    | Хосты                        |
| -------------------------------- | -------------------------- | ---------------------------- |
| Текстовые и офисные документы    | `common-documents`         | CLI, Electron, PWA, VS Code  |
| Все общие ресурсы                | `universal-asset-explorer` | Electron, PWA, VS Code       |
| Моды и данные StarCraft II       | `sc2-mod-studio`           | Electron, VS Code            |
| Карты и данные Warzone 2100      | `warzone-2100-studio`      | Electron, VS Code            |
| Проверка общих ресурсов без окна | `headless-mod-ci`          | CLI, server, automation host |

Подписанный RC содержит платформу, общий bundle и два игровых bundle: SC2 и Warzone. Состояние
профилей можно проверить командой `pnpm profiles:check`.

## 4. Найдите установки игр

Игровое расширение принимает только проверенный корень установки. Приоритет одинаков и
предсказуем: сначала пути из настроек хоста, затем переменная окружения, затем известные системные
места. Диски и закрытый каталог `WindowsApps` рекурсивно не сканируются.

Для SC2 кандидат должен содержать активную запись `.build.info` и согласованный набор
`SC2Data/config`, `SC2Data/data` и `SC2Data/indices`. Для Warzone кандидат должен вести к
`data/base.wz` с ZIP-сигнатурой; установщик Windows Store, записи удаления, Steam и обычные места
проверяются ограниченным поиском.

Самый простой ручной override в PowerShell действует только в текущем процессе и его дочерних
процессах:

```powershell
$env:MODKITX_SC2_ROOT = 'C:\Games\StarCraft II'
$env:MODKITX_WARZONE_ROOT = 'C:\Games\Warzone 2100'
pnpm --filter @modkitx-x3/electron-app start
```

Указывайте корень игры, а не отдельный архив или исполняемый файл. Плохой путь не становится
доверенной установкой: проверка просто отвергнет его и продолжит со следующими кандидатами.

Хост, который читает переносимый `SettingsDocument`, может передать несколько ручных путей в
заданном порядке:

```json
{
  "schemaVersion": 1,
  "appearance": { "theme": "modkit-dark", "density": "compact" },
  "extensions": [],
  "gameInstallations": {
    "org.modkitx/starcraft-2": {
      "configuredPaths": ["C:\\Games\\StarCraft II"]
    },
    "org.modkitx/warzone-2100": {
      "configuredPaths": ["C:\\Games\\Warzone 2100"]
    }
  },
  "recent": [],
  "disabledContributions": []
}
```

Это формат переносимых настроек хоста, а не имя готовой настройки VS Code. Если приложение пока не
показывает редактор игровых путей, используйте переменную окружения; не добавляйте неизвестный
ключ в настройки приложения.

## 5. Безопасно запустите карту SC2

Запуск карты поддерживается только как явное действие совместимого настольного хоста на Windows.
Игровое расширение создаёт неизменяемый план для
`Support64/SC2Switcher_x64.exe`, а общий Node-хост перед запуском заново проверяет:

- живое явное разрешение `process-launch`;
- подтверждённую установку SC2 и её реальные пути;
- абсолютный локальный путь карты;
- существование карты, `SC2Switcher_x64.exe` и рабочего каталога.

Исполняемый файл и рабочая папка обязаны остаться внутри реального корня установки. План сохраняет
точные проверенные старые аргументы:
`-run <map> -preload 1 -NoUserCheats -meleeMod Void -difficulty 2 -speed 2 -displaymode 1`. Процесс
запускается без shell. Если хост не показывает явное действие запуска, поддерживаемого обходного
пути через ручной вызов executable нет. Автоматические тесты используют внедрённый подменный
spawner и настоящую игру не открывают.

## 6. Соберите и установите подписанный RC

Закрытый Ed25519-ключ должен находиться вне репозитория. Путь вывода должен быть свежим и ещё не
существовать:

```powershell
pnpm release:rc -- --out <FRESH-RC> --signing-key <PRIVATE-KEY-OUTSIDE-REPO>
pnpm release:verify -- --out <FRESH-RC> --public-key <PUBLIC-KEY>
pnpm release:install -- --out <FRESH-RC> --target <INSTALL-STORE> --public-key <PUBLIC-KEY>
```

Проверка подтверждает Ed25519-подпись манифеста, SHA-256, размеры и наличие артефактов. Установка
создаёт неизменяемую версию внутри `<INSTALL-STORE>/versions` и печатает точный активный `root`.

Для обновления повторите `release:install` с новой папкой RC и тем же `<INSTALL-STORE>`. Для
возврата к последней прошлой версии выполните:

```powershell
pnpm release:rollback -- --target <INSTALL-STORE>
```

Обе версии сохраняются. RC не меняет PATH, реестр Windows, файловые ассоциации или меню «Пуск».
Краткая памятка поставляется вместе с RC и хранится в
[scripts/release/INSTALL.md](../scripts/release/INSTALL.md).

## 7. Если что-то не работает

- `pnpm install --frozen-lockfile` падает: проверьте Node 22+, pnpm 10+ и неизменённый lockfile.
- `pnpm build` сообщает drift: не правьте сгенерированный файл вручную; запустите указанный в
  ошибке emit-скрипт и проверьте diff.
- `release:rc` отвергает output: выберите путь, которого ещё нет.
- `release:verify` отвергает подпись или digest: не устанавливайте RC и получите правильную пару
  RC/публичный ключ.
- SC2 не найдена: корнем должна быть папка с `.build.info` и `SC2Data`, а не `Versions` или
  `Support64`.
- Warzone не найдена: корень должен вести к настоящему `data/base.wz`; не пытайтесь вручную
  обходить права `WindowsApps`.
- Запуск SC2 отклонён: это ожидаемо без Windows, подтверждённой установки, существующей карты и
  свежего разрешения `process-launch`.
- Откат недоступен: в хранилище ещё нет прошлой версии либо её папка была удалена вручную.

## 8. Разработка расширений

Не копируйте сюда полное описание ABI. Создание расширений, варианты исполнения, безопасность и
установка tarball во внешний проект уже описаны в
[руководстве разработчика](./GUIDE_DEVELOPER_RU.md). Тест
[out-of-tree-extension.test.ts](../scripts/test/out-of-tree-extension.test.ts) создаёт отдельный
временный проект и проверяет, что Electron, VS Code и PWA загружают именно установленный digest, а
не исходники workspace.

## 9. Явные границы

- Подтверждён только локальный Windows x64 путь; Linux и macOS пока не прошли итоговый прогон.
- Это не публичный релиз, не npm-публикация и не обещание готовых подписанных нативных приложений.
- Multiverse не входит в Focused Product GA и начинается только после отдельного решения владельца.
- C&C Tiberium Wars, Red Alert 3 и Beyond All Reason остаются после Multiverse и текущей остановки.
- Автоматическая проверка не заменяет личное тестирование владельцем перед будущей публикацией.
