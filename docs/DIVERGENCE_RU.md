# Осознанные расхождения modkitX3 с каноном

Дата решения: 2026-08-24

Статус: принято владельцем для лаборатории X3; promotion не разрешена

Этот реестр хранит только намеренные расхождения формы. Он не заменяет
[целевое состояние](./TARGET_STATE_RU.md),
[план паритета](../PLAN_PARITY_RU.md) или
[исполняемый блок 8](../PLAN_SOL_BLOCK8_2026-08-24.md).

## D-EXT-1. Дробность расширений определяется независимостью

Канон преимущественно собирает кодеки одной игры в одно расширение. X3 оставляет отдельно то,
что осмысленно подключается без остальных частей семейства или тянет собственную зависимость.
Цель — минимальная доказуемая сборка: независимость видна по package boundary и проверяется
app-set/bundle gates, а не предполагается из tree-shaking.

Blizzard уже доказывает правило фактическим графом зависимостей:

| Расширение                 | Собственные зависимости |
| -------------------------- | ----------------------- |
| `blizzard/casc`            | `fflate`                |
| `blizzard/mpq`             | —                       |
| `blizzard/models`          | `@xmldom/xmldom`        |
| `blizzard/starcraft2`      | —                       |
| `blizzard/galaxy-language` | —                       |
| `blizzard/starcraft2-game` | `@rgrove/parse-xml`     |

Сливать их в одно игровое расширение нельзя: пользователь MPQ не должен получать CASC, M3 и
SC2 GameData вместе с их зависимостями.

### Решение для EA перед расселением блока 8

Все текущие EA staging-пакеты зависят только от `@modkitx-x3/codec-kit`; тяжёлых частных
зависимостей у них нет. Поэтому дробность фиксируется по самостоятельно подключаемой функции:

| Целевое расширение | Содержимое                                                  | Решение и основание                                                                                                                         |
| ------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `ea/archives`      | `mix`                                                       | Самостоятельный контейнер Westwood, полезный без моделей и игровых данных.                                                                  |
| `ea/big`           | `big`                                                       | Самостоятельный контейнер SAGE для многих игр EA; отделён от C&C 3 semantic codecs.                                                         |
| `ea/emperor`       | `emperor-rfh-rfd`, `emperor-xbf`                            | Компактная пара одной asset-цепочки Emperor; одинаковые зависимости, отдельное подключение не уменьшает closure.                            |
| `ea/models`        | `sage-w3x`, `westwood-w3d`                                  | Один опциональный модельный вклад с общим `model-scene-source`; нет частной зависимости одного codec-а.                                     |
| `ea/sage`          | `cnc3-data`, `cnc3-localization`, `cnc3-map`, `sage-skudef` | Одна небольшая C&C/SAGE semantic vertical без внешних зависимостей; каждый contribution остаётся отдельно отключаемым политикой приложения. |
| `ea/tiberian-sun`  | `red-alert2-vxl`                                            | Самостоятельная воксельная модельная семья.                                                                                                 |
| `ea/westwood`      | `cps`, `r16`, `r8`, `shp`, `tmp`, `vpl`, `wsa`              | Общая dependency-free палитровая media-семья; codec contributions переключаются раздельно.                                                  |

Если любой codec позже получает частную тяжёлую зависимость или самостоятельный продуктовый
набор, это основание пересмотреть только соответствующую строку. Молчаливое слияние и дробление
запрещены.

## D-EXT-2. Внутренняя раскладка codec source остаётся лабораторной

Каноническая форма:

```text
<семейство>/codecs/<кодек>/src/index.ts
```

Текущая форма X3:

```text
<семейство>/src/<кодек>/codec.js
```

В блоке 8 выравниваются группы и package boundaries, но не внутренняя раскладка. Массовая смена
layout смешала бы механический переезд с функциональным углублением и затруднила доказательство
отсутствия регрессий. Решение о канонической раскладке принимается только в отдельной promotion
slice после разрешения владельца.

## D-SAGE-1. `sage-asset-bundle` не материализуется без входа и runtime

Каноническая запись находится ровно в
`extensions/ea/sage/codecs/sage-asset-bundle/codec.manifest.json`. Это единственный файл в
каталоге codec-а: `status` равен `unsupported`, вариант `planned` имеет
`availability: unavailable`, пустые `entrypoints` и `capabilities`, а причина записана как
`No SAGE asset-bundle grouping, index, or extraction runtime is implemented.` Канон не содержит
ни parser/source, ни fixture/test. Game manifest C&C 3 только `suggests` этот ID; исполняемой
зависимости нет.

Поэтому X3 не создаёт contribution, probe или фиктивную запись в `ports:check`: расширения
`.manifest`, `.bin`, `.imp`, `.relo`, `.version` и `.cdata` сами по себе недостаточны для
надёжного выбора primary source и группировки multi-file bundle. Текущий минимум остаётся
`168/168`, а не искусственно увеличивается на недоказанный codec.

Отдельная follow-up задача перед портом:

1. получить законно доступный corpus хотя бы одного полного набора
   `.manifest` + `.bin` + `.imp` + `.relo` + `.version` и связанных `.cdata`;
2. зафиксировать grouping key, обязательность файлов и выбор primary source;
3. разделить смешанные канонические `file`/`directory` source kinds на доказуемую single/bundle
   или namespace topology MK3;
4. реализовать bounded index/extraction runtime и negative fixtures;
5. только после product-owned `openSubject` acceptance добавить contribution, corpus case и
   поднять ожидаемый итог `ports:check`.

До выполнения этих условий это отсутствие является подтверждённой канонической границей, а не
долгом, который можно закрыть metadata-only заглушкой.

## Проверка

- `pnpm apps:check` доказывает точные продуктовые наборы.
- `pnpm check:extensions` доказывает валидность каждого authored extension container.
- `pnpm bundle:check` охраняет опубликованные entrypoints и минимальные сборки.
- `pnpm ports:check` переносит, а не удаляет, гарантию codec-а при смене дома.
