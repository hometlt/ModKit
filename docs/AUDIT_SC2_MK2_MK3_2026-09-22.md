## Вывод

MK3 уже имеет полезную основу: контрактные Data/Language/References-сервисы, VFS, композицию контейнеров и зависимостей, типизированные операции и управляемые leases. Но наличие сервиса, команды или карточки **не доказывает сквозную работоспособность пользовательского сценария MK2**. Основной риск сейчас — несколько разных представлений одной карты/мода: дерево, языковой контекст, карточка и resolved workspace могут иметь разный набор зависимостей и разные правила обновления.

Аудит выполнялся в двух рабочих деревьях с большим количеством ранее существовавших изменений. Исходные HEAD: core `fe330f42`, Blizzard `7dbb3afd`. Во время работы появились также параллельные изменения renderer/model cache, не относящиеся к этому аудиту. Они не откатывались. Это проверка текущего checkout, не сертификация воспроизводимого релиза из чистого commit.

Скриншоты пользователя использованы как критерии MK2, а не как доказательство состояния запущенного MK3. Проверки с синтетическими пакетами отдельно от проверки настоящей игровой установки. Реальные файлы игры/CASC напрямую не исследовались. Запрошенный `PROMPT.txt` в workspace, корнях обоих репозиториев и проверенных родительских каталогах не найден.

## Архитектура и модульность

### Что сделано хорошо

- `packages/sdk` задаёт общие контракты; UI, LSP и MCP могут использовать одни владельцы форматов вместо отдельных реализаций SC2.
- `packages/host/src/content-dependencies.ts` проецирует provider mounts в ограниченный workspace. Тесты проверяют порядок слоёв, precedence, fingerprints/revisions и честные incomplete/unavailable-результаты.
- Контейнерная композиция отделяет carrier от семантического пакета. Есть проверки разрешения ресурсов внутри контейнера без подмены внешним filesystem origin.
- Модель leases, cancellation и resource budgets уже существует. Это хорошая основа для больших карт и нескольких одновременно открытых модов.
- В Blizzard есть AST-проверка границ и ratchet миграционного долга. Gate сообщает о 84 оставшихся legacy records, а не объявляет миграцию законченной.
- Есть отдельные synthetic, owner, real и installed acceptance проверки. Их результаты важно не смешивать.

### Что требует доработки

1. **Resources overlay не равен calculated workspace.** `apps/vscode/src/resource-chain.ts` объединяет одинаковые ID и берёт facts последнего слоя. Это не вычисление defaults, parent inheritance, удаления массивов, констант или ссылок. Нельзя называть такое дерево полным resolved-model только потому, что видны Core/Liberty/Void.
2. **VS Code самостоятельно восстанавливает пути зависимостей.** `dependencyLayersOf` в `apps/vscode/src/extension.ts` использует знание `Mods/Campaigns` и sibling paths. Для произвольной пользовательской карты вне такой структуры это не эквивалент public content-source resolution. Дереву нужен тот же workspace/context и owner provenance, что LSP и MCP, без второй схемы поиска файлов.
3. **Граница платформы не выдерживается полностью.** `node scripts/check-app-imports.mjs` сообщил 88 нарушений на 769 файлах. Значительная часть — общие scene/renderer-модули, зависящие от `@modkit/codec-kit`. `check-external-composition.mjs` также не проходит. Последний использует широкий текстовый regexp, поэтому его список надо разобрать на runtime-зависимости, комментарии и generated assets; нельзя автоматически считать каждый матч отдельным дефектом.
4. **Не превращать ratchet в разрешение нового долга.** Повторно используемые format-neutral geometry/raster/math primitives следует выделять в низкоуровневый общий владелец; SC2-семантику оставлять Blizzard-модулям. Не исправлять gate удалением проверок или расширением baseline.
5. **Состояние сборки и состояние исходников расходятся.** Часть тестов импортирует portable/dist, а не изменённый source. Их успех до пересборки ничего не доказывает о новой правке. Manual-authoring launcher использует mtime-кэш, не учитывающий удаления файлов надёжно, и по умолчанию кладёт extension folder, а не VSIX. Receipt должен различать тип артефакта, hash и source revision.
6. **Скрипт manual-authoring перезаписывает тестовые fixtures/settings.** Для пользовательских ручных проверок нужен отдельный новый output-каталог либо явный reset-fixtures. Не запускать его поверх каталога с ценными ручными изменениями.

## Исправления дерева в этом аудите

Изменены `apps/vscode/src/resource-chain.ts` и его regression tests:

- Используются собственные root ID каждого слоя; недоступный активный слой не скрывает доступные базовые.
- Запросы дочерних узлов идут только слоям, реально объявившим узел.
- Числовые значения больше не складываются как предполагаемые счётчики. Для объединённой ветви preview явно сообщает количество уникальных **непосредственных children**, а не произвольную сумму ресурсов/статистик. Typed facts остаются facts владельца.
- Поиск идёт по видимому объединённому дереву: нет дублей и совпадений только с затёртым старым значением.
- Ошибки чтения и отмена не маскируются под пустую ветвь; временную ошибку открытия можно повторить.
- Недоступные слои обозначаются как incomplete, включая отдельную диагностическую строку.
- Убрано молчаливое усечение после 50 000 узлов; повторяющийся cursor теперь даёт явную ошибку.
- Dispose прерывает lifetime операций, освобождает каждый lease один раз и запрещает повторное открытие после unmount.

Это исправление навигационного слоя, **не** замена доменного merge engine. Вычислять общий итог по всем листьям только ради цифры рядом с категорией пока не предлагается: это заставит раскрывать весь граф при отрисовке корня.

В Blizzard `mod-card.ts` дополнительно исправлены адреса объявлений: используется общий position-aware XML scanner и Data schema, а не предположение `UnitData.xml`. Поддержаны смешанные custom/include XML, одинарные кавычки, XML entities, корректные UTF-16 ranges; комментарии и вложенные теги не принимаются за объявления. Последнее объявление берётся в порядке загруженной `Map`, не алфавитного списка Files. Defaults получили стабильные ID по классу вместо индекса массива. Preload удалён из семантических категорий, сам файл остался в Files. Три новых source-теста и scoped mod typecheck прошли. S-defaults и constants этим исправлением не добавлены.

## Аудит LSP/MCP

Подробный отчёт с exact commands, file:line и всеми отрицательными результатами: [AUDIT_SC2_LSP_MCP_2026-09-22.md](AUDIT_SC2_LSP_MCP_2026-09-22.md).

Исправлено:

- Shared provenance references не считаются циклами; настоящие циклы и ограничения проекции сохранены.
- Ограниченный stdio frame теперь вмещает допустимый language overlay с JSON escaping; прежний 1 MiB лимит противоречил допустимому размеру документа. Реальный large-overlay stdio тест прошёл.

Что хорошо: публичные contracts, discovery, typed read-only/edit workflows, retained outputs, revision guards и явная неполнота. Что ещё доработать:

1. Инвалидация diagnostics зависимых документов при правке другого файла; queue ordering сам по себе этого не обеспечивает.
2. Обновление dependency/root/locale topology после startup и понятный статус incomplete для definition/references, где обычный LSP-array теряет этот признак.
3. Единый reservation-based лимит handles при конкурентных opens; deadline/отмена зависшего provider при close.
4. Отдельная безопасная передача больших rename/workspace edits: capped JSON projection нельзя применять как полную транзакцию.
5. Стабилизировать SC2 integration: artifact-digest-mismatch, fallback Strings→TXT, packed-dependency provider unresolved и Style rename при incomplete workspace. Защитные отказы не отключать ради зелёных тестов.

После исправления двух ошибочных ожиданий самого smoke-теста фактический public stdio прогон прошёл **2/2**. Он проверил Galaxy definition, bounded semantic tokens, update/stale refusal и close, затем Data `edit.field` → prepare → commit → reopen с новой revision → undo → redo → undo/discard. Inventory при этом честно был `partial`, definition — `partial`. Этот synthetic результат подтверждает адаптерный happy path, но не снимает перечисленные ниже failures packed dependencies/installed providers на других fixtures.

## Особенно полезные MCP-сценарии для карт и модов

Публичные имена ниже проверены в регистрации сервера; конкретные service/operation/subject ID нужно брать из ответа discovery, не конструировать по предположению. Наличие операции ещё не означает поддержку каждой карты/мода.

| Задача моддера | Полезные методы | Почему полезно |
|---|---|---|
| Открыть правильную карту с зависимостями | `capabilities`, `inventory`, `discover_installations`, `open_subject`/`open_discovered`, `inspect`, `open_resolved_workspace` | Явный выбранный контекст вместо случайного XML-файла. Важно читать completeness и missing dependencies. |
| Найти Unit/Effect/Ability и узнать итоговые значения | `search_subjects`, `list_subjects`, `select_subject`, `subject_facts` | Canonical ID, страничная выборка, значения вместе с источником. |
| Понять, кто использует эффект, модель или строку | `relation_graph` | Ограниченный inbound/outbound граф; полезен для удаления, переноса и поиска побочных эффектов. |
| Объяснить баланс Unit/Weapon | `subject_calculations` | Публикуемые владельцем расчёты и предположения; не подменять unsupported расчёт самодельной формулой DPS. |
| Найти допустимые поля, enums и контракты | `knowledge_search`, `knowledge_resolve`, `service_operations` | Снижает число выдуманных полей и неверных ссылок, особенно в сложных Abil/Actor definitions. |
| Изменить shared Effect только для одной Unit | `subject_isolation`, `subject_isolation_plan` | Предварительно видны referrers, clone и rewire; не менять общий объект вслепую. |
| Изменить inherited значение в своём моде | `subject_edit_target`, `propose_resolved_edit`, `prepare_edit`, `commit_edit` | Проверяемая writable destination и guarded revisions. После commit — повторное чтение результата; при отказе не обходить сервис прямой записью XML. |
| Проверить unsaved Data/Galaxy/Layout/Strings | `language_session_open`, `language_session_update`, `language_session_feature`, `language_session_close` | Diagnostics, completion, definition/references поверх конкретной версии документа и workspace context. |
| Получить поддержанный preview/export/validation | `inspect` → `invoke_readonly` с advertised ID | Повторное использование владельца формата, retained output при необходимости; не угадывать название операции. |

Все методы имеют префикс `modkit.`. Завершать работу через `close_selected_subject`, `close_subject`, `language_session_close`, `release_output`: retained handles не должны накапливаться в долгой AI-сессии.

Практический default для AI: страницы по 20 элементов, не более пяти страниц без сужения запроса; graph depth 3, maxNodes/maxEdges 100. Capped/incomplete ответ не доказывает отсутствие ссылок.

Приоритет новых MCP-возможностей — не ещё один универсальный `execute`, а безопасные сценарии поверх имеющихся контрактов: bounded batch диагностика ссылок/локализаций, compare двух revisions/load orders, provenance explanation по полю, отчёт missing assets/locale keys. Предложения нужно реализовать owner-side и открыть одновременно UI/LSP/MCP, а не делать отдельный парсер внутри MCP.

## Приоритет доработок

### P0 — согласованная модель и корректные записи

1. Один resolved workspace/context с revision/fingerprint для Resources, LSP, MCP, subject cards и localization. Тест: Core → dependency → пользовательский мод → dirty overlay; один объект должен иметь одинаковое значение и provenance во всех поверхностях.
2. Для inherited/read-only данных показывать источник и writable override target. Изменение карточки или ячейки не должно записывать в CASC или в зависимость. Все записи через typed plan/prepare/commit с revision precondition и undo/redo.
3. Проверять mutation результат и read-back, а не только отсутствие exception. Не отправлять UI сообщение об успехе, если операция refused/conflicted/incomplete.
4. Не выдавать incomplete/unsupported за пустой список или нулевое значение.

### P1 — пользовательская полнота MK2

- Единая provenance-навигация к конкретному объявлению и диапазону; повторный переход активирует уже открытый editor. Include/custom XML, повторное объявление и dirty buffer обязательны в тестах.
- Tree должен получать семантические children от владельцев: Layout Frames/templates/constants; Style styles/constants; Galaxy functions/variables/types; EditorCategories groups; Data entities/defaults/constants. Наличие списка файлов категории не означает наличие этих символов.
- Data namespaces `Unit/Abil/Weapon` не следует автоматически отождествлять с файловыми dataspaces/includes. Скоуп констант и defaults должен исходить из Data-owner semantics, а не из имени файла или порядка UI-узлов.
- Files: отдельные Images/Audio/Models/Animations/Facial animations и другие категории референсируемых ресурсов. Индексировать metadata/references; не загружать бинарные payload только для построения дерева.
- В resolved XML и parent chain показывать не только вычисленный результат, но и ограничения контекста, missing parent/cycle и происхождение значения.
- Для localization критичен сквозной сценарий: таблица → редактирование → токены/completion → preview `<d ref>`/styles → сохранение → reopen/undo. Одних text-language completion tests недостаточно.

### P2 — оптимизация без усложнения

- Кэшировать результаты по workspace revision, набору dependency fingerprints, locale и dirty-overlay version. Не кешировать unsupported/failed opening навсегда как отсутствие данных.
- Убрать повторные парсеры и path heuristics из платформенного UI; использовать owner indexes и public context services.
- Измерять отдельно cold open, warm expansion, completion P50/P95, отмену mount, peak memory и сохранение одной ячейки. Не ускорять только первый кадр ценой неконтролируемой фоновой загрузки.
- Single-flight для одной операции/контекста и ограниченная параллельность между слоями. Пагинация допустима, но continuation должен продлевать список и сообщать неполноту.
- Убрать build outputs, `reports` и исторические generated snapshots из рабочего архитектурного индекса. Текущий knowledge graph включает dist/renderer и oracle-dependencies: его fan-in/hotspots загрязнены сборочными артефактами.
- Закрепить воспроизводимый isolated VSIX acceptance с artifact hash и exact extension roots, чтобы исключить повторение «тестируется старая версия».
