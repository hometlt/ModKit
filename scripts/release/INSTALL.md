# Установка локального Modkit MK3 RC

Подписанный RC предназначен для локальной проверки Focused Product GA. Он не публикует пакеты, не
регистрирует системное приложение и не является публичным выпуском. Итоговая проверка этого пути
выполнена только на Windows x64.

## Требования

- Node.js 22 или новее;
- pnpm 10 или новее;
- папка RC с `release-manifest.json` и `release-signature.json`;
- доверенный публичный Ed25519-ключ автора этой сборки.

Команды ниже выполняются из чистого checkout Modkit MK3. Пути можно задавать абсолютными или
относительно корня репозитория.

## Проверка и первая установка

Сначала отдельно проверьте подпись, контрольные суммы и размеры всех файлов:

```powershell
pnpm release:verify -- --out <RC> --public-key <PUBLIC-KEY>
```

Затем установите RC в локальное хранилище:

```powershell
pnpm release:install -- --out <RC> --target <INSTALL-STORE> --public-key <PUBLIC-KEY>
```

Команда ещё раз проверяет RC, распаковывает только безопасные обычные файлы в неизменяемую папку
`<INSTALL-STORE>/versions/<manifest-sha256>/root` и атомарно записывает активную версию в
`<INSTALL-STORE>/installation-state.json`. Точный путь активного `root` печатается в ответе.

## Обновление

Для обновления установите новую подписанную папку RC в то же хранилище:

```powershell
pnpm release:install -- --out <NEW-RC> --target <INSTALL-STORE> --public-key <PUBLIC-KEY>
```

Старая версия остаётся на месте и автоматически попадает в историю отката.

## Откат

Чтобы снова активировать последнюю предыдущую версию, выполните:

```powershell
pnpm release:rollback -- --target <INSTALL-STORE>
```

Откат не удаляет текущую или предыдущую версию. Если истории ещё нет либо папка прошлой версии
исчезла, команда завершится ошибкой без частичного переключения.

## Сборка собственного RC

Сначала соберите и полностью проверьте чистый checkout:

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm check
```

Создайте свежий путь, которого ещё не существует, и передайте закрытый Ed25519-ключ из папки вне
репозитория:

```powershell
pnpm release:rc -- --out <FRESH-RC> --signing-key <PRIVATE-KEY-OUTSIDE-REPO>
pnpm release:verify -- --out <FRESH-RC> --public-key <PUBLIC-KEY>
```

В RC входят платформа, общий набор расширений, профили `sc2-mod-studio` и
`warzone-2100-studio`, а также SBOM, сведения о лицензиях и эта инструкция. Код Blizzard и
Warzone в архив платформы не копируется: репозитории `modkit-blizzard` и `modkit-warzone` должны
лежать рядом с `modkitX3`, либо их пути задаются через `MODKIT_BLIZZARD_ROOT` и
`MODKIT_WARZONE_ROOT`. Подпись Ed25519 защищает манифест, а манифест хранит SHA-256 и размер
каждого артефакта.

Если исходники или эта инструкция менялись, сопровождающий сначала обновляет воспроизводимые
release-метаданные командой `pnpm release:emit`, а затем повторяет `pnpm release:check`. Закрытый
ключ никогда не сохраняется в репозитории.

## Если установка не проходит

- `unknown argument` означает опечатку либо аргумент после команды без разделителя `--`.
- `release output must be a fresh path` означает, что папка для новой сборки уже существует.
- Ошибка подписи, SHA-256 или размера означает, что RC или ключ не совпадают; такой RC не ставьте.
- Ошибка безопасного пути означает, что архив содержит недопустимое имя или тип файла; не
  распаковывайте его вручную как обход проверки.
- Если откат недоступен, сначала убедитесь, что это хранилище уже обновлялось и его папки `versions`
  не удалялись вручную.

В исходном checkout полная последовательность и границы выпуска описаны в
`docs/FOCUSED_GA_LOCAL_GUIDE.md`. Сам RC не дублирует весь каталог документации.
